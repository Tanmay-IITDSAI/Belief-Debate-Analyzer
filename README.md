## DebateGPT Data Contract

DebateGPT is public under CC-BY-SA-4.0 according to the current problem statement. The download path is:

```text
data/raw/debategpt/
```

Verified public source: `https://huggingface.co/datasets/frasalvi/debategpt`.
Verified revision: `ff19fc4cd38424023b8db616f7358a9b94e4c9d5`.

The parser must validate the four paired 1–5 fields per participant:

```text
agreementPreTreatment
agreementPostTreatment
sideAgreementPreTreatment
sideAgreementPostTreatment
```

Semantics:

- `agreementPreTreatment` / `agreementPostTreatment`: proposition-level belief agreement before and after the debate.
- `sideAgreementPreTreatment` / `sideAgreementPostTreatment`: agreement with the opponent’s side; complementary behavioral evidence only.

Required primary filter:

```text
condition == human-human
```

The exact condition column/value must be verified from the downloaded DebateGPT export before analysis. Do not assume a condition name if the file uses a documented variant.

## PDF Evaluation Plan

- **H1:** Fleiss’ kappa over human labels for stance-change causes; expected `>= 0.60`, falsified `< 0.40`.
- **H2:** Overall attribution accuracy `>= 0.70`, falsified `< 0.55`; F1 thresholds: evidence adoption `>= 0.75`, anchoring `>= 0.65`, echo `>= 0.60`, strategic persuasion `>= 0.55`; also confusion matrix and accuracy split by joint versus divergent proposition/side movement.
- **H3:** Workbench utility gain `>= 20` percentage points, falsified `< 10`, plus time-to-answer.
- **H4:** Four ablations: no rhetorical annotation, no stance layer, no echo detection, and no priority order. The no-priority condition reports per-signal accuracy. Rhetorical removal is expected to cause the largest drop, at least 10 points; `<5` falsifies that expectation.
- **H5:** Pearson correlation between normalized change over DebateGPT proposition agreement and normalized change over system `S_t`; expected `r >= 0.50`, falsified `< 0.20`.
- **H6:** CW-POR-adapted rate using normalized rhetorical JSD magnitude as the weight, not an LLM judge’s confidence; expected `>= 0.65`, falsified `< 0.45`. The numerator is strategic flags coinciding with increased side agreement without corresponding proposition-agreement movement.

These are preregistered targets, not results.

## Model Contract

The updated PDF specifies a prompted Llama-3.1-8B-Instruct rhetorical scorer following Ji et al.’s four-strategy typology, with scores in `[0,1]` for causal, empirical, emotional, and moral. This prompted-LLM path is the documented default and must not be blocked on finding a Ji Hugging Face classifier.

A fine-tuned classifier may be supplied later through the pluggable interface, but it must be independently verified. The previous guessed repository `ji-et-al-2025/rhetorical-strategy-roberta` was checked and returned 404; it is not a valid default.

The stance computation must remain exactly:

```text
z_t = z_(t-1) + alpha * q_t * sign(e_t) - beta * abs(S_(t-1))
S_t = tanh(z_t / 2)
z_0 = 0
```

where `q_t` is normalized LLM quality on a 1–5 scale, `e_t` is in `{-1,+1}`, and alpha/beta are fixed evidence-uptake and anchoring weights.

Attribution signals and priority must remain exactly:

1. evidence adoption;
2. strategic persuasion;
3. echo/peer influence;
4. anchoring.

The signal definitions are the PDF’s thresholds: quality `>0.6`, own-prior similarity `>0.8`, peer similarity `>0.75`, JSD `>0.3` with causal/empirical to emotional/moral shift and large stance change.

## Installable Package

No build step is required; the repository *is* the package.

```bash
# Python 3.10+ recommended (GPU required only for backend="hf" modes)
pip install -r requirements.txt

# 1) Static reviewer demo (no GPU, no token, instant)
#    Open demo_site/index.html in any browser, or host the folder statically
#    (e.g. Netlify; a netlify.toml is included).

# 2) Interactive workbench
export HF_TOKEN=<your read-access token>   # only for the two live modes
streamlit run app.py
```

The workbench has three modes:

1. **Browse a real DebateGPT example** — no GPU/token; loads precomputed
   real output from `demo_site/data.json` instantly. The reliable on-stage path.
2. **Generate a new debate live** — GPU + HF_TOKEN; drives the real
   `backend="hf"` pipeline end-to-end. Output is sanitized and validated
   (stage directions, instruction echo, and cross-speaker leakage are
   stripped/retried) and is qualitative-only per the project rules.
3. **Upload transcript JSON** — GPU + HF_TOKEN; analyzes any transcript in
   the canonical schema. `random.json` is a ready-made sample to try it.

HF_TOKEN is read from the environment or entered in the sidebar (kept for
the session only, never stored or logged). Llama-3.1-8B-Instruct is gated:
accept the license on its model page with the same HF account.
